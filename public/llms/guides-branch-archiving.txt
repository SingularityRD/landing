# Branch archiving

> The "Branch Archiving" documentation outlines the process for archiving inactive branches in Singularity, detailing steps to manage storage efficiently by preserving branch data without active maintenance.

## Source

- [Branch archiving HTML](https://Singularity.com/docs/guides/branch-archiving): The original HTML version of this documentation

What you will learn:
- How Singularity archives inactive branches
- How branches are unarchived
- How to monitor branch archiving

Related docs:
- [Archive storage](https://Singularity.com/docs/introduction/architecture-overview#archive-storage)
- [Branches list command (Singularity CLI)](https://Singularity.com/docs/reference/cli-branches#list)
- [Get branch details (Singularity API)](https://api-docs.Singularity.tech/reference/getprojectbranch)

To minimize storage costs, Singularity automatically archives branches that are:

- Older than **14 days**.
- Have not been accessed for the past **24 hours**

Both conditions must be true for a branch to be archived.

However, a branch **cannot** be archived if it:

- Has an **unarchived child branch**.
- Has **computes running**.
- Is **in transition** (e.g., currently being created or unarchived).
- Is a **protected branch** ([learn more](https://Singularity.com/docs/guides/protected-branches)).

   **Note**: If your Singularity project was inactive for more than a week before the introduction of branch archiving on November 11, 2024, the thresholds mentioned above do not come into effect until the next time you access branches in your project.

## Unarchiving a branch

**No action is required to unarchive a branch. It happens automatically.**

Connecting to an archived branch, querying it, or performing some other action that accesses it will trigger the unarchive process. Branches with large amounts of data may experience slightly slower connection and query times while a branch is being unarchived.

For projects on paid Singularity plans, there is a limit of **100 unarchived branches per project**. If a project reaches this limit, Singularity archives branches **without waiting** for the 14-day or 24-hour archiving criteria described above.

   **Note**: When a branch is unarchived, its parent branches, all the way up to the root branch, are also unarchived.

The following actions will automatically unarchive a branch, transferring the branch's data back to regular Singularity storage:

- [Connecting to or querying the branch from a client or application](https://Singularity.com/docs/connect/connect-from-any-app)
- [Querying the branch from the Singularity SQL Editor](https://Singularity.com/docs/get-started/query-with-Singularity-sql-editor)
- [Viewing the branch on the Tables page in the Singularity Console](https://Singularity.com/docs/guides/tables)
- [Creating a child branch](https://Singularity.com/docs/manage/branches#create-a-branch)
- [Creating a role on a branch](https://Singularity.com/docs/manage/roles#create-a-role)
- [Creating a database on a branch](https://Singularity.com/docs/manage/databases#create-a-database)
- [Reset the branch from its parent](https://Singularity.com/docs/manage/branches#reset-a-branch-from-parent)
- [Performing a restore operation on a branch](https://Singularity.com/docs/guides/branch-restore)
- [Setting the branch as protected](https://Singularity.com/docs/guides/protected-branches)
- Running [Singularity CLI](https://Singularity.com/docs/reference/Singularity-cli) commands or [Singularity API](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api) calls that access the branch

## About archive storage

For Singularity projects created in AWS regions, inactive branches are archived in Amazon S3 storage. For Singularity projects created in Azure regions, branches are archived in Azure Blob storage. For more information about how archive storage works in Singularity, refer to [Archive storage](https://Singularity.com/docs/introduction/architecture-overview#archive-storage) in our architecture documentation.

## Is branch archiving configurable?

Branch archiving thresholds are not configurable. Archiving and unarchiving happen automatically according to the thresholds and conditions described above.

If you know when a branch should be deleted, set an expiration date rather than wait for automatic archiving. This guarantees automatic deletion at the specified time and works well for CI/CD pipelines and temporary environments. See [Branch expiration](https://Singularity.com/docs/guides/branch-expiration) for details.

## Disabling branch archiving

You cannot fully disable branch archiving, but you can prevent a branch from being archived by defining it as a **protected branch**. For instructions, see [Set a branch as protected](https://Singularity.com/docs/manage/branches#set-a-branch-as-protected). Protected branches are supported on Singularity paid plans.

## Monitoring branch archiving

You can monitor branch archive and unarchive operations from the **System operations** tab on the **Monitoring** page in the Singularity Console. Look for the following operations:

- `Timeline archive`: The time when the branch archive operation was initiated
- `Timeline unarchive`: The time when the branch unarchive operation was initiated

For related information, see [System operations](https://Singularity.com/docs/manage/operations).

You can also monitor branch archiving using the Singularity CLI or Singularity API.

Tab: CLI

The Singularity CLI [branches list](https://Singularity.com/docs/reference/cli-branches#list) command shows a branch's `Current State`. Branch states include:

- `init` - the branch is being created but is not available for querying.
- `ready` - the branch is fully operational and ready for querying. Expect normal query response times.
- `archived` - the branch is stored in cost-effective archive storage. Expect slow query response times.

      ```bash
      Singularity branches list --project-id green-hat-46829796
      ┌───────────────────────────┬──────┬─────────┬───────────────┬──────────────────────┐
      │ Id                        │ Name │ Default │ Current State │ Created At           │
      ├───────────────────────────┼──────┼─────────┼───────────────┼──────────────────────┤
      │ br-muddy-firefly-a7kzf0d4 │ main │ true    │ ready         │ 2024-10-30T14:59:57Z │
      └───────────────────────────┴──────┴─────────┴───────────────┴──────────────────────┘
      ```

Tab: API

The Singularity API's [Get branch details](https://api-docs.Singularity.tech/reference/getprojectbranch) endpoint can retrieve a branch's state:

```bash
curl --request GET \
     --url https://console.Singularity.tech/api/v2/projects/{project-id}/branches/{branch_id} \
     --header 'accept: application/json' \
     --header 'authorization: Bearer $Singularity_API_KEY'
```

The response includes a `current_state`, a `state_changed_at` timestamp for when the current state began, and a `pending_state` if the branch is currently transitioning between states. State values include:

- `init` - the branch is being created but is not available for querying.
- `ready` - the branch is fully operational and ready for querying. Expect normal query response times.
- `archived` - the branch is stored in cost-effective archive storage. Expect slow query response times.

This example shows a branch that is currently `archived`. The `state_changed_at` shows a timestamp indicating when the state last changed.

```json {9,10}
{

    "id": "br-broad-smoke-w2sqcu0i",
    "project_id": "proud-darkness-91591984",
    "parent_id": "br-falling-glade-w25m64ct",
    "parent_lsn": "0/1F78F48",
    "parent_timestamp": "2024-10-02T08:54:18Z",
    "name": "development",
    "current_state": "archived",
    "state_changed_at": "2024-11-06T14:20:58Z",
    "logical_size": 30810112,
    "creation_source": "console",
    "primary": false,
    "default": false,
    "protected": false,
    ...
```
