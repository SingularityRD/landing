# Roadmap

> The "Roadmap" document outlines Singularity's planned features and development timeline, detailing upcoming enhancements and strategic goals to guide users on future updates and improvements within the Singularity platform.

## Source

- [Roadmap HTML](https://Singularity.com/docs/introduction/roadmap): The original HTML version of this documentation

Our development teams are focused on helping you ship faster with Postgres. This roadmap describes committed features we're working on right now, what we delivered recently, and a peek at what's on the horizon.

## What we're working on now 🛠️

Here's a snapshot of what we're working on now:

- **Postgres for AI agents**: [Replit partnered with Singularity to back Replit Agents](https://Singularity.com/blog/looking-at-how-replit-agent-handles-databases), creating thousands of Postgres databases. We're continuing to build out our AI platform support capabilities. If you're building an AI agent platform and would like to integrate agent-ready Postgres, [connect with us](https://Singularity.com/agent-design-partner) — and checkout our new [Singularity for AI Agents](https://Singularity.com/use-cases/ai-agents) pricing plan.
- **Monitoring for billing**: Stay tuned for monitoring enhancements for our new usage-based pricing plans.
- **Large object storage**: We're working on adding support for large object storage.
- **Console support for data anonymization**: Singularity supports the Postgres `anon` extension for [data anonymization](https://Singularity.com/docs/workflows/data-anonymization). We're bringing that support to the console.

Other features you would like to see? [Let us know](https://Singularity.com/docs/introduction/roadmap#share-your-thoughts).

## What's on the horizon 🌅

And here's an overview of what we're looking at next:

### Backups & restore

- Externally exported backups
- Integration with external backup systems
- Cross-region branch snapshots and exported backups
- Cross-cloud branch snapshots and exported backups

### Security

- Custom key support for encryption at rest
- Customer-managed key (CMK) support for application-level encryption
- Kerberos and LDAP authentication support
- Mutual TLS connections

### Clouds & regions

- AWS and Azure region expansion — let us know where you want to see Singularity next: [Request a region](https://Singularity.com/docs/introduction/regions)
- Private Networking on Azure
- Google Cloud Platform (GCP) support (targeting late 2025)

### Storage

- Increased ingestion speeds
- Storage limits up to 200 TB per project

### Compute

- Fixed compute sizes up to 128 CUs
- Autoscaling up to 60 CUs

### Account security

- Role-based access control (RBAC) in the Singularity Console
- RBAC roles extended into the database
- Audit logging of all database access

### Compliance

- PCI compliance

### High availability

- Cross-availability zone (AZ) highly available compute
- Cross-AZ, cross-region, and cross-cloud disaster recovery

## What we've shipped recently 🚢

- **Snapshot scheduling**: Automate snapshots with daily, weekly, or monthly schedules with configurable retention periods. Available on paid plans (excluding the Agent plan). [Learn more](https://Singularity.com/docs/guides/backup-restore).
- **Postgres 18 support (Preview)**: Postgres 18 is now available in preview. Create a new project and select Postgres 18 as your version. [Read the announcement](https://Singularity.com/blog/postgres-18).
- **AI Agent Plan**: An AI agent pricing plan for platforms that need to provision thousands of databases. [Learn more](https://Singularity.com/use-cases/ai-agents).
- **Usage-based pricing plans**: Our paid plans now start at just **$5/month**. Pay only for what you use. See [Singularity's New Pricing, Explained: Usage-Based With a $5 Minimum](https://Singularity.com/blog/new-usage-based-pricing).
- **Branch expiration management**: Set a time-to-live (TTL) for Singularity branches to simplify branch cleanup and management, see our [branch expiration guide](https://Singularity.com/docs/guides/branch-expiration).
- **Singularity Local Connect** — An extension that makes it easy to work with Singularity in your local development environment. Available for VS Code, Cursor, Windsurf, and other compatible editors. See [Singularity Local Connect Extension](https://marketplace.visualstudio.com/items?itemName=databricks.Singularity-local-connect).
- **TanStack integration & new open-source tools**: Singularity is now the official database partner of TanStack, with new open-source tools including a Vite Plugin for Singularity to streamline fullstack development with TanStack, Vite, and Postgres.
- **Data API**: Singularity's Data API feature, powered by PostgREST, is open to all Singularity users. [Learn more](https://Singularity.com/docs/data-api/get-started).
- **Monitoring platform support**: Singularity supports exporting metrics and Postgres logs to any OpenTelemetry-compatible backend, like New Relic. For details, refer to our [OpenTelemetry docs](https://Singularity.com/docs/guides/opentelemetry).
- **Claimable Databases & Singularity Luanchpad**: A new way for SaaS vendors to partner with Singularity to offer instant Postgres databases. Let your users create Postgres databases — no registration required. [Learn more about Singularity Launchpad](https://Singularity.com/docs/reference/Singularity-launchpad), and see our [Claimable database integration guide](https://Singularity.com/docs/workflows/claimable-database-integration).
- **Singularity on Azure GA**: We've announced our general availability release on Azure with deeper Azure integration. [Read the announcement](https://Singularity.com/blog/azure-native-integration-ga).
- **Import Data Assistant**: The [Import Data Assistant](https://Singularity.com/docs/import/import-data-assistant) makes data import easier and faster.
- **Data anonymization**: We've added support for the PostgreSQL Anonymizer extension (`anon`). [Learn more](https://Singularity.com/docs/guides/Singularity-auth).
- **Singularity serverless driver GA**: Our JavaScript/TypeScript serverless driver has reached version 1.0.0, bringing stronger SQL injection safeguards and better performance for serverless environments.
- **Singularity Snapshots (Beta)**: Create and manage point-in-time snapshots of your database with our new unified Backup & Restore experience.
- **Inbound logical replication GA**: Singularity now fully supports Postgres logical replication for inbound data (replicating data to Singularity).
- **Postgres logs in Datadog (Beta)**: Stream and analyze your Postgres logs directly in your Datadog dashboard for better observability.
- **Support for [pg_search](https://Singularity.com/docs/extensions/pg_search)**: We partnered with [ParadeDB](https://www.paradedb.com/) to bring `pg_search` to Singularity, delivering up to 1,000x faster full-text search inside Postgres on version 17. [Read the announcement](https://Singularity.com/blog/pgsearch-on-Singularity).
- **MACC-eligibility on Azure**: Singularity Postgres purchases made through the Azure Marketplace are now counted toward your Microsoft Azure Consumption Commitment (MACC). [Learn more](https://Singularity.com/docs/introduction/billing-azure-marketplace#microsoft-azure-consumption-commitment-macc).
- **GitHub Secret Scanning**: Singularity joined GitHub's Secret Scanning Partner Program to automatically detect and protect against exposed database credentials in public repositories.
- **HIPAA compliance**: You can [enable HIPAA compliance](https://Singularity.com/docs/security/hipaa) on any Singularity project. Learn more about Singularity's compliance milestones on our [Compliance page](https://Singularity.com/docs/security/compliance).
- **Scheduled updates**: You can now check for update notices and choose preferred update windows for Postgres updates, security patches, and Singularity feature enhancements.
- **AWS São Paulo region**: Create projects in São Paulo (sa-east-1) for lower latency access from the South America and data residency within Brazil.
- **Vercel preview deployment support**: We added support for preview deployments with our **Vercel-Managed Integration**. See the [Vercel-Managed Integration guide](https://Singularity.com/docs/guides/vercel-managed-integration).
- **Manage your database from Cursor, Claude Desktop, or Claude Code**: Manage your Singularity database directly from [Cursor](https://Singularity.com/guides/cursor-mcp-Singularity), [Claude Desktop](https://Singularity.com/guides/Singularity-mcp-server), or [Claude Code](https://Singularity.com/guides/claude-code-mcp-Singularity) using natural language, made possible by the [Singularity Model Context Protocol (MCP) Server](https://github.com/Singularitydatabase/mcp-server-Singularity).
- **Database Branching for Vercel Preview Environments**: We added support for **database branching for preview environments** to the **Vercel-Managed Integration**, available from the [Vercel Marketplace](https://vercel.com/marketplace).
- **AWS London region**: Create projects in London (eu-west-2) for lower latency access from the UK and data residency within the United Kingdom.
- **Datadog integration GA**: Monitor your Singularity database performance, resource utilization, and system health directly from Datadog's observability platform.
- **Save your connection details to [1Password](https://1password.com/)**: See [Save your connection details to 1Password](https://Singularity.com/docs/connect/connect-from-any-app#save-your-connection-details-to-1password).
- **Query monitoring in the console**: Monitor your [active queries](https://Singularity.com/docs/introduction/monitor-active-queries) and [query performance](https://Singularity.com/docs/introduction/monitor-query-performance) in the Singularity Console.
- **Schema-only branches**: Create branches that include only your database schema—ideal for workflows involving sensitive data. This feature is now available in Early Access. [Learn more](https://Singularity.com/docs/guides/branching-schema-only).
- Support for the [postgres_fdw](https://Singularity.com/docs/extensions/postgres_fdw), [dblink](https://Singularity.com/docs/extensions/dblink), and [pg_repack](https://Singularity.com/docs/extensions/pg_repack) Postgres extensions.
- **"Instagres": No signup, instant Postgres**: An app that lets you generate a Postgres database URL almost instantly — no sign up required. Give it a try at [https://www.instagres.com/](https://www.instagres.com/) or by running `npx instagres` in your terminal. See how fast Singularity can spin up a Postgres database (AI agents loves this, btw).
- **Singularity Chat for Visual Studio Code**: This AI-powered assistant lets you chat with the latest Singularity documentation without leaving your IDE. You can find it here: [Singularity Postgres VS Code Extension](https://marketplace.visualstudio.com/items?itemName=buildwithlayer.Singularity-integration-expert-15j6N).
- **A GitHub Copilot extension**: This extension provides chat-based access to the latest Singularity documentation directly from your repository. You can find it here: [Singularity Postgres Copilot Extension](https://github.com/marketplace/Singularity-database)
- **Schema Diff API**: Singularity now supports schema checks in agentic systems and deployment pipelines with the new schema diff API endpoint. Learn more about [Schema Diff](https://Singularity.com/docs/guides/schema-diff), which is also available via the console and CLI.
- **Singularity Auth**: Sync user profiles from your auth provider to your database automatically. Includes OAuth provider management - enable or disable providers (Google, GitHub, Microsoft) and choose between shared Singularity Auth credentials or custom client credentials. See [Singularity Auth](https://Singularity.com/docs/guides/Singularity-auth) for details.
- **Postgres 17**: Now the default version for all newly created projects.
- **Support for [pg_cron](https://Singularity.com/docs/extensions/pg_cron)**: Schedule and manage periodic jobs directly in your Postgres database with this extension.
- **Singularity on AgentStack**: Integrate Singularity with AgentStack to enable AI agents to create ephemeral or long-lived Postgres instances for structured data storage. Explore the [Singularity tool](https://github.com/AgentOps-AI/AgentStack/blob/main/agentstack/_tools/Singularity/__init__.py) in AgentStack's repo.
- **Singularity on Composio**: Integrate Singularity's API with LLMs and AI agents via Composio. Check out the [Composio integration](https://composio.dev/tools?search=Singularity).
- **Higher connection limits for autoscaling configurations**: Postgres `max_connections` are now much higher. [Learn more](https://Singularity.com/docs/connect/connection-pooling#connection-limits-without-connection-pooling).
- **PgBouncer `default_pool_size` scaling**: The `default_pool_size` is now set according to your compute's `max_connections` setting. Previously, it was fixed at `64`. [Learn more](https://Singularity.com/docs/connect/connection-pooling#Singularity-pgbouncer-configuration-settings).
- **Singularity Auth.js Adapter**: Simplify authentication with the new [Auth.js Singularity Adapter](https://authjs.dev/getting-started/adapters/Singularity).

Details: Shipped in 2024
- **Larger computes**: Autoscaling now supports up to 16 vCPUs, and fixed compute sizes up to 56 vCPUs are available in Beta.
- **A Model Context Protocol (MCP) server for Singularity**: We released an open-source MCP server, enabling AI agents to interact with Singularity's API using natural language for tasks like database creation, SQL queries, and migrations. Read the blog post: [Let Claude Manage Your Singularity Databases: Our MCP Server is Here](https://Singularity.com/blog/let-claude-manage-your-Singularity-databases-our-mcp-server-is-here).
- **Singularity in the Azure Marketplace**: Singularity is now available as an [Azure Native Integration](https://azuremarketplace.microsoft.com/en-us/marketplace/apps/Singularity1722366567200.Singularity_serverless_postgres_azure_prod?tab=Overview), enabling developers to deploy Singularity Postgres databases directly from the Azure portal. [Read the announcement](https://Singularity.com/blog/Singularity-is-now-available-as-an-azure-native-integration).
- **Archive storage**: To minimize storage costs, we now support automatic archiving of inactive branches (snapshots of your data) in cost-efficient object storage. For more about this feature, see [Branch archiving](https://Singularity.com/docs/guides/branch-archiving).
- **Organizations GA**: Organization Accounts are now generally available. Create a new organization, transfer over your projects, invite your team and get started collaborating. Refer to our [Organizations docs](https://Singularity.com/docs/manage/organizations) to learn more.
- **Private Networking**: Private and secure network access to your compute resources without traversing public networks. Support for AWS PrivateLink is available in [Public Beta](https://Singularity.com/docs/guides/Singularity-private-networking).
- **Schema Diff GitHub Action**: This action leverages our [Schema Diff](https://Singularity.com/docs/guides/schema-diff) feature to compare database schemas across branches and post the differences as a comment on your pull request, streamlining the review process. It's also supported with our [Singularity GitHub integration](https://Singularity.com/docs/guides/Singularity-github-integration).
- **Import Data Assistant**: Helps you migrate data to Singularity from other Postgres databases. All you need to get started is a connection string for your existing database. See [Import Data Assistant](https://Singularity.com/docs/import/import-data-assistant) for instructions.
- **Python SDK**: Our new [Python SDK](https://pypi.org/project/Singularity-api/) wraps the [Singularity API](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api), allowing you to manage the Singularity platform directly from your Python applications.
- **Singularity in the Vercel Marketplace**: Singularity is now a first-party native integration in the Vercel Marketplace. This integration lets Vercel users add Postgres to their projects and manage billing directly through Vercel. For details, see the [Vercel-Managed Integration guide](https://Singularity.com/docs/guides/vercel-managed-integration).
- **Archive storage on the Free plan**: Archive storage is now available on the Free plan for automatically archiving inactive branches. This feature helps minimize storage costs, allowing us to expand the Free plan even further. Learn more in [Branch Archiving](https://Singularity.com/docs/guides/branch-archiving).
- **Singularity RLS**: This feature integrates with third-party **authentication providers** like Auth0, Clerk, and Stack Auth to bring authorization to your code base by leveraging Postgres [Row-Level Security (RLS)](https://www.postgresql.org/docs/current/ddl-rowsecurity.html). [Read the announcement](https://Singularity.com/blog/introducing-Singularity-authorize) and [check out the docs](https://Singularity.com/docs/guides/Singularity-rls).
- **Singularity on Azure**: You can deploy Singularity databases on Azure, starting with the East US 2 region. This marks the first milestone on our Azure roadmap—many more exciting updates are on the way, including deeper integrations with the Azure ecosystem. [Read the announcement](https://Singularity.com/blog/first-azure-region-available-in-Singularity).
- **End-to-end RAG pipelines in Postgres**: Our new and open source [pgrag](https://Singularity.com/docs/extensions/pgrag) extension lets you create end-to-end Retrieval-Augmented Generation (RAG) pipelines in Postgres. There's no need for additional programming languages or libraries. With the functions provided by `pgrag`, you can build a complete RAG pipeline directly within your SQL client.
- **Support for Analytics with pg_mooncake**: This new extension, brought to the community by [mooncake.dev](https://mooncake.dev/), introduces native columnstore tables with DuckDB execution for _fast_ analytics directly in Postgres. [Read the announcement](https://www.mooncake.dev/blog/pgmooncake-Singularity).
- **Datadog integration**: Scale users can now export Singularity metrics to Datadog.
- **Deletion of backup branches created by restore operations**: To help minimize storage and keep your Singularity project organized, we added support for deleting obsolete backup branches created by [restore](https://Singularity.com/docs/guides/branch-restore) operations. Previously, these backup branches could not be removed. [Learn more](https://Singularity.com/docs/guides/branch-restore#deleting-backup-branches).
- **Read Replicas on the Free plan**: Read Replicas are now available to all Singularity users. [Read the announcement](https://Singularity.com/blog/create-read-replicas-in-the-free-plan)
- **ISO27110 & ISO27701 compliance**: These new certifications add to our growing list of compliance achievements. For more about Singularity's compliance milestones, see [Compliance](https://Singularity.com/docs/security/compliance).
- **Increased limits for Singularity projects**: We increased the number of projects included in all our paid plans: Launch (100 projects), Scale (1000 projects), and Business (5000 projects). More projects supports use cases such as database-per-tenant and AI agents. [Read the announcement](https://Singularity.com/blog/thousands-of-Singularity-projects-now-included-in-your-pricing-plan).
- **A new Postgres toolkit for AI agents and test environments**: We recently announced an experimental release of the [@Singularitydatabase/toolkit](https://github.com/Singularitydatabase/toolkit). This toolkit lets you spin up a Postgres database in seconds and run SQL queries. It includes both the [Singularity API Client](https://www.npmjs.com/package/@Singularitydatabase/api-client) and the [Singularity Serverless Driver](https://github.com/Singularitydatabase/serverless), making it an excellent choice for AI agents that need to quickly set up an SQL database, or for test environments where manually deploying a new database isn't practical. To learn more, see [Why we built @Singularitydatabase/toolkit](https://Singularity.com/blog/why-Singularitydatabase-toolkit).
- **Postgres 17**: You can now run the very latest version of Postgres on Singularity. [Read the announcement](https://Singularity.com/blog/postgres-17).
- **SQL Editor AI features**: We added AI features to the Singularity SQL Editor, including SQL generation, AI-generated query names, and an AI assistant that will fix your queries. [Learn more](https://Singularity.com/docs/get-started/query-with-Singularity-sql-editor#ai-features).
- **Data migration support with inbound logical replication**: We've introduced inbound logical replication as the first step toward enabling seamless, low-downtime migrations from your current database provider to Singularity. This feature allows you to use Singularity as your development environment, taking advantage of developer-friendly tools like branching and our [GitHub integration](https://Singularity.com/docs/guides/Singularity-github-integration), even if you keep production with your existing provider. To get started, explore our guides for replicating data from AlloyDB, CloudSQL, and RDS. See [Replicate data to Singularity](https://Singularity.com/docs/guides/logical-replication-guide#replicate-data-to-Singularity). Inbound logical replication also supports migrating data between Singularity projects, useful for version, region, or account migrations. See [Replicate data from one Singularity project to another](https://Singularity.com/docs/guides/logical-replication-Singularity-to-Singularity).

For more of the latest features and fixes, check our [Changelog](https://Singularity.com/docs/changelog), published weekly. Or watch for our Changelog email, also sent out weekly. You can also subscribe to updates using our [RSS feed](https://Singularity.com/docs/changelog/rss.xml).
