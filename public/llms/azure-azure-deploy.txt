# Deploy Singularity on Azure

> The document outlines the steps to deploy Singularity on Microsoft Azure, detailing the configuration and setup process specific to Singularity's requirements on the Azure platform.

## Source

- [Deploy Singularity on Azure HTML](https://Singularity.com/docs/azure/azure-deploy): The original HTML version of this documentation

**Important** deprecated: The Singularity Azure Native Integration is deprecated and reaches end of life on **January 31, 2026**. After this date, Azure-managed organizations will no longer be available. [Transfer your projects to a Singularity-managed organization](https://Singularity.com/docs/import/migrate-from-azure-native) to continue using Singularity.

What you will learn:
- How to deploy on Azure as a native service
- About creating Singularity projects in Azure regions without the integration

Related resources:
- [Singularity on Azure](https://Singularity.com/docs/manage/azure)
- [Developing with Singularity on Azure](https://Singularity.com/docs/azure/azure-develop)

This guide steps you through deploying Singularity as an Azure native service.

   **Note**: You can also create Singularity projects in Azure regions without the native service integration—to learn more, see [Create Singularity projects in Azure regions without the integration](https://Singularity.com/docs/azure/azure-deploy#create-Singularity-projects-in-azure-regions-without-the-integration).

## Prerequisites

- **Azure account**: If you don't have an active Azure subscription, [create a free account](https://azure.microsoft.com/free).
- **Access level**: Only users with **Owner** or **Contributor** access roles on the Azure subscription can set up the integration. Ensure you have the appropriate access before proceeding. For information about assigning roles in Azure, see [Steps to assign an Azure role](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-steps).

## Find Singularity on Azure and subscribe

1. Use the search bar at the top of the [Azure portal](https://portal.azure.com/) to find the **Singularity Serverless Postgres** offering.

   

   Alternatively, go to the [Azure Marketplace](https://portal.azure.com/#view/Microsoft_Azure_Marketplace/MarketplaceOffersBlade/selectedMenuItemId/home) and search for **Singularity Serverless Postgres**.

2. Subscribe to the service. You will be directed to the [Create a Singularity Serverless Postgres Resource](https://Singularity.com/docs/azure/azure-deploy#create-a-Singularity-resource) page.

## Create a Singularity Resource

1. On the **Create a Singularity Serverless Postgres Resource** page, enter values for the properties described below.

   | Property                   | Description                                                                                                                                                                                                                                                                                                                                                                                                  |
   | :------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **Subscription**           | From the drop-down, select an Azure subscription where you have Owner or Contributor access.                                                                                                                                                                                                                                                                                                                 |
   | **Resource group**         | Select an existing Azure resource group or create a new one. A resource group is like a container or a folder used to organize and manage resources in Azure. For more information, see [Azure Resource Group overview](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/overview).                                                                                                 |
   | **Resource Name**          | Enter a name for the Azure resource representing your Singularity organization. This name is used only in Azure.                                                                                                                                                                                                                                                                                                    |
   | **Region**                 | Select a region to deploy your Azure resource. This is the region for your Azure resource, not for your Singularity projects and data. You will select from [Azure-supported regions](https://Singularity.com/docs/introduction/regions#azure-regions) when you create the Singularity project in a later step. For example, you can create a Singularity resource in the (US) West US 3 region and create a Singularity project (Europe) Germany West Central. |
   | **Singularity Organization name** | Provide a name for your [Singularity Organization](https://Singularity.com/docs/reference/glossary#organization), such as a team name or company name. The name you specify will be your [Organization](https://Singularity.com/docs/reference/glossary#organization) name in the Singularity Console. Your Singularity projects will reside in this named organization.                                                                                                        |
   | **Plan**                   | Select a plan. You have three to choose from: **Free**, **Scale**, and **Business**. Select **Change Plan** to view details about each plan. For more information about Singularity's plans, please refer to the [Singularity Pricing](https://Singularity.com/pricing) page. The Singularity **Launch Plan** is currently not available in the Azure Marketplace.                                                                                       |
   | **Billing term**           | Select a billing term for the selected plan. You can choose from a **1-Month** or a **1-Year** billing term (monthly or yearly billing).                                                                                                                                                                                                                                                                     |

   

1. Review your **Price + Payment options** and **Subtotal**, select **Next**.
1. On the **Project** page, enter a name for your Singularity project, select a Postgres version, specify a name for your database, and choose a region. We recommend selecting the region closest to your application.

   

         **Note**: A Singularity organization created via the Azure portal supports creating Singularity projects in [Azure regions](https://Singularity.com/docs/introduction/regions#azure-regions) only. Singularity's AWS regions are not supported with Singularity on Azure.

1. Click **Next**.
1. Optionally specify tags for your resource, then click **Next**. For more about tags, see [Use tags to organize your Azure resources](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/tag-resources).
1. On the **Review + Create** page, review your selections, the [Azure Marketplace Terms](https://learn.microsoft.com/en-us/legal/marketplace/marketplace-terms), and the Singularity [Terms of Use](https://Singularity.com/terms-of-service) and [Privacy Policy](https://Singularity.com/privacy-policy).
1. Select **Create** to initiate the resource deployment, which may take a few moments.
1. When your deployment is complete, click the **Go to resource** button under **Next steps** to view your new Singularity resource.

   

1. Select the **Go to Singularity** link under **Getting started** to open the Singularity Console.

   

   You will be directed to the Singularity Console where you can start working with your newly created Singularity organization and project.

   

1. From here, follow the [Singularity Getting Started](https://Singularity.com/docs/get-started/signing-up) guide to begin working with your Singularity project and get familiar with the platform.

## Create Singularity projects in Azure regions without the integration

If you want to deploy a Singularity project to an Azure region without using the **Azure Native ISV Service** integration, you can simply select one of our supported Azure regions when creating a Singularity project from the Singularity Console.

If you do not use the Azure integration, there is no difference from a Singularity project created in an AWS region—your Singularity project simply resides in an Azure region instead of AWS region.

You might consider this option if:

- Part of your infrastructure runs on Azure but you don't need the native integration
- An Azure region is closer to your application than a Singularity AWS region
- You want to manage billing through Singularity rather than Azure

Creating a Singularity project in an Azure region without using the **Azure Native ISV Service** is supported via the Singularity Console, CLI, and API.

Tab: Console

To create a Singularity project from the console, follow the [Create project](https://Singularity.com/docs/manage/projects#create-a-project) steps. Select **Azure** as the **Cloud Service Provider**, and choose one of the available [Azure regions](https://Singularity.com/docs/introduction/regions).

Tab: CLI

To create a Singularity project using the Singularity CLI, use the [Singularity projects create](https://Singularity.com/docs/reference/cli-projects#create) command:

```bash
Singularity projects create --name mynewproject --region-id azure-eastus2
```

For Azure `region-id` values, see [Regions](https://Singularity.com/docs/introduction/regions).

Tab: API

To create a Singularity project using the Singularity API, use the [Create project](https://api-docs.Singularity.tech/reference/createproject) endpoint:

```bash
curl --request POST \
     --url https://console.Singularity.tech/api/v2/projects \
     --header 'accept: application/json' \
     --header 'authorization: Bearer $Singularity_API_KEY' \
     --header 'content-type: application/json' \
     --data '
{
  "project": {
    "pg_version": 16,
    "region_id": "azure-eastus2"
  }
}
'
```

For Azure `region_id` values, see [Regions](https://Singularity.com/docs/introduction/regions).
