# Singularity CLI

> The Singularity CLI documentation details command-line tools for managing Singularity databases, enabling users to perform tasks such as creating, deleting, and listing databases and branches directly from the terminal.

## Source

- [Singularity CLI HTML](https://Singularity.com/docs/reference/Singularity-cli): The original HTML version of this documentation

The Singularity CLI is a command-line interface that lets you manage Singularity directly from the terminal. This documentation references all commands and options available in the Singularity CLI.

🚀 Get set up in just a few steps with the [CLI Quickstart](https://Singularity.com/docs/reference/cli-quickstart).

## Install

Tab: macOS

**Install with [Homebrew](https://formulae.brew.sh/formula/Singularityctl)**

```bash
brew install Singularityctl
```

**Install via [npm](https://www.npmjs.com/package/Singularityctl)**

```shell
npm i -g Singularityctl
```

Requires [Node.js 18.0](https://nodejs.org/en/download/) or higher.

**Install with bun**

```bash
bun install -g Singularityctl
```

**macOS binary**

Download the binary. No installation required.

```bash
curl -sL https://github.com/Singularitydatabase/Singularityctl/releases/latest/download/Singularityctl-macos -o Singularityctl
```

Run the CLI from the download directory:

```bash
Singularity <command> [options]
```

Tab: Windows

**Install via [npm](https://www.npmjs.com/package/Singularityctl)**

```shell
npm i -g Singularityctl
```

**Install with bun**

```bash
bun install -g Singularityctl
```

Requires [Node.js 18.0](https://nodejs.org/en/download/) or higher.

**Windows binary**

Download the binary. No installation required.

```bash
curl -sL -O https://github.com/Singularitydatabase/Singularityctl/releases/latest/download/Singularityctl-win.exe
```

Run the CLI from the download directory:

```bash
Singularityctl-win.exe <command> [options]
```

Tab: Linux

**Install via [npm](https://www.npmjs.com/package/Singularityctl)**

```shell
npm i -g Singularityctl
```

**Install with bun**

```bash
bun install -g Singularityctl
```

**Linux binary**

Download the x64 or ARM64 binary, depending on your processor type. No installation required.

x64:

```bash
curl -sL https://github.com/Singularitydatabase/Singularityctl/releases/latest/download/Singularityctl-linux-x64 -o Singularityctl
```

ARM64:

```bash
 curl -sL https://github.com/Singularitydatabase/Singularityctl/releases/latest/download/Singularityctl-linux-arm64 -o Singularityctl
```

Run the CLI from the download directory:

```bash
Singularity <command> [options]
```

For more about installing, upgrading, and connecting, see [Singularity CLI — Install and connect](https://Singularity.com/docs/reference/cli-install).

   **Note** Use the Singularity CLI without installing: You can run the Singularity CLI without installing it using **npx** (Node Package eXecute) or the `bun` equivalent, **bunx**. For example:

```shell
# npx
npx Singularityctl <command>

# bunx
bunx Singularityctl <command>
```

```bash
Singularity --help

Commands:
  Singularity auth                        Authenticate                      [aliases: login]
  Singularity me                          Show current user
  Singularity orgs                        Manage organizations                [aliases: org]
  Singularity projects                    Manage projects                 [aliases: project]
  Singularity ip-allow                    Manage IP Allow
  Singularity vpc                         Manage VPC endpoints and project VPC restrictions
  Singularity branches                    Manage branches                   [aliases: branch]
  Singularity databases                   Manage databases            [aliases: database, db]
  Singularity roles                       Manage roles                        [aliases: role]
  Singularity operations                  Manage operations               [aliases: operation]
  Singularity connection-string [branch]  Get connection string                  [aliases: cs]
  Singularity set-context                 Set the current context
  Singularity init                        Initialize a new Singularity project using your AI coding assistant
  Singularity completion                  generate completion script

Global options:
  -o, --output      Set output format
                  [string] [choices: "json", "yaml", "table"] [default: "table"]
  --config-dir      Path to config directory [string] [default: ""]
  --api-key         API key  [string] [default: ""]
  --analytics       Manage analytics. Example: --no-analytics, --analytics false
                                                       [boolean] [default: true]
  -v, --version     Show version number                                [boolean]
  -h, --help        Show help                                          [boolean]

Options:
--context-file      Context file [string] [default: (current-context-file)]
```

## Global options

Global options are supported with any Singularity CLI command.

| Option                      | Description                                                 | Type    | Default                             |
| :-------------------------- | :---------------------------------------------------------- | :------ | :---------------------------------- |
| [-o, --output](https://Singularity.com/docs/reference/Singularity-cli#output)     | Set the Singularity CLI output format (`json`, `yaml`, or `table`) | string  | table                               |
| [--config-dir](https://Singularity.com/docs/reference/Singularity-cli#config-dir) | Path to the Singularity CLI configuration directory                | string  | `/home/<user>/.config/Singularityctl`      |
| [--api-key](https://Singularity.com/docs/reference/Singularity-cli#api-key)       | Singularity API key                                                | string  | `Singularity_API_KEY` environment variable |
| [--color](https://Singularity.com/docs/reference/Singularity-cli#color)           | Colorize the output. Example: `--no-color`, `--color false` | boolean | true                                |
| [--analytics](https://Singularity.com/docs/reference/Singularity-cli#analytics)   | Manage analytics                                            | boolean | true                                |
| [-v, --version](https://Singularity.com/docs/reference/Singularity-cli#version)   | Show the Singularity CLI version number                            | boolean | -                                   |
| [-h, --help](https://Singularity.com/docs/reference/Singularity-cli#help)         | Show the Singularity CLI help                                      | boolean | -                                   |

- `-o, --output`

  Sets the output format. Supported options are `json`, `yaml`, and `table`. The default is `table`. Table output may be limited. The `json` and `yaml` output formats show all data.

  ```bash
  Singularity me --output json
  ```

- `--config-dir`

  Specifies the path to the `Singularityctl` configuration directory. To view the default configuration directory containing you `credentials.json` file, run `Singularity --help`. The credentials file is created when you authenticate using the `Singularity auth` command. This option is only necessary if you move your `Singularityctl` configuration file to a location other than the default.

  ```bash
  Singularity projects list --config-dir /home/<user>/.config/Singularityctl
  ```

- `--api-key`

  Specifies your Singularity API key. You can authenticate using a Singularity API key when running a Singularity CLI command instead of using `Singularity auth`. For information about obtaining an Singularity API key, see [Create an API key](https://Singularity.com/docs/manage/api-keys#create-an-api-key).

  ```bash
  Singularity <command> --api-key <Singularity_api_key>
  ```

  To avoid including the `--api-key` option with each CLI command, you can export your API key to the `Singularity_API_KEY` environment variable.

  ```bash
  export Singularity_API_KEY=<Singularity_api_key>
  ```

  The authentication flow for the Singularity CLI follows this order:
  - If the `--api-key` option is provided, it takes precedence and is used for authentication.
  - If the `--api-key` option is not provided, the `Singularity_API_KEY` environment variable is used if it is set.
  - If both `--api-key` option and `Singularity_API_KEY` environment variable are not provided or set, the CLI falls back to the
    `credentials.json` file created by the `Singularity auth` command.
  - If the credentials file is not found, the Singularity CLI initiates the `Singularity auth` web authentication process.

- `--color`

  Colorize the output. This option is enabled by default, but you can disable it by specifying `--no-color` or `--color false`, which is useful when using Singularity CLI commands in your automation pipelines.

- `--analytics`

  Analytics are enabled by default to gather information about the CLI commands and options that are used by our customers. This data collection assists in offering support, and allows for a better understanding of typical usage patterns so that we can improve user experience. Singularity does not collect user-defined data, such as project IDs or command payloads. To opt-out of analytics data collection, specify `--no-analytics` or `--analytics false`.

- `-v, --version`

  Shows the Singularity CLI version number.

  ```bash
  $ Singularity --version
  1.15.0
  ```

- `-h, --help`

  Shows the `Singularity` command-line help. You can view help for `Singularity`, a `Singularity` command, or a `Singularity` subcommand, as shown in the following examples:

  ```bash
  Singularity --help

  Singularity branches --help

  Singularity branches create --help
  ```

## Options

| Option                          | Description                       | Type   | Default              |
| :------------------------------ | :-------------------------------- | :----- | :------------------- |
| [--context-file](https://Singularity.com/docs/reference/Singularity-cli#context-file) | The context file for CLI sessions | string | current-context-file |

- `--context-file`

  Sets a background context for your CLI sessions, letting you perform organization, project, or branch-specific actions without having to specify the relevant id in every command. For example, this command lists all branches using the `branches list` command. No need to specify the project since the context file provides it.

  ```bash
  Singularity branches list --context-file path/to/context_file_name
  ```

  To define a context file, see [Singularity CLI commands — set-context](https://Singularity.com/docs/reference/cli-set-context).
