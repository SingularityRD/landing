# System operations

> The "System operations" document outlines procedures for managing and maintaining Singularity database systems, detailing tasks such as monitoring, scaling, and troubleshooting to ensure optimal performance and reliability.

## Source

- [System operations HTML](https://Singularity.com/docs/manage/operations): The original HTML version of this documentation

An operation is an action performed by the Singularity Control Plane on a Singularity object or resource. Operations are typically initiated by user actions, such as creating a branch or deleting a database. Other operations may be initiated by the Singularity Control Plane, such as suspending a [compute](https://Singularity.com/docs/reference/glossary#compute) after a period of inactivity or checking its availability. You can monitor operations to keep an eye on the overall health of your Singularity project or to check the status of specific operations. When working with the Singularity API, you can poll the status of operations to ensure that an API request is completed before issuing the next API request. For more information, see [Poll operation status](https://Singularity.com/docs/manage/operations#poll-operation-status).

| Operation              | Description                                                                                                                                                                                                                                                                                                                      |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Apply config`         | Applies a new configuration to a Singularity object or resource. For example, changing compute settings or creating, deleting, or updating Postgres users and databases initiates this operation.                                                                                                                                       |
| `Apply storage config` | Applies a new configuration to a Singularity storage object or resource. For example, updating the restore window for a project initiates this operation.                                                                                                                                                                               |
| `Check availability`   | Checks the availability of data in a branch and that a [compute](https://Singularity.com/docs/reference/glossary#compute) can start on a branch. Branches without a compute are not checked. This operation, performed by the [availability checker](https://Singularity.com/docs/reference/glossary#availability-checker), is a periodic load generated by the Control Plane. |
| `Create branch`        | Creates a [branch](https://Singularity.com/docs/reference/glossary#branch) in a Singularity project. For related information, see [Manage branches](https://Singularity.com/docs/manage/branches).                                                                                                                                                                                    |
| `Create timelime`      | Sets up storage and creates the default branch when a Singularity [project](https://Singularity.com/docs/reference/glossary#project) is created.                                                                                                                                                                                                               |
| `Delete tenant`        | Deletes stored data when a Singularity project is deleted.                                                                                                                                                                                                                                                                              |
| `Start compute`        | Starts a compute when there is an event or action that requires compute resources. For example, connecting to a suspended compute initiates this operation.                                                                                                                                                                      |
| `Suspend compute`      | Suspends a compute after a period of inactivity. For information about how Singularity manages compute resources, see [Compute lifecycle](https://Singularity.com/docs/introduction/compute-lifecycle/).                                                                                                                                                       |
| `Tenant attach`        | Attaches a Singularity project to storage.                                                                                                                                                                                                                                                                                              |
| `Tenant detach`        | Detaches a Singularity project from storage after the project as been idle for an extended period.                                                                                                                                                                                                                                      |
| `Tenant reattach`      | Reattaches a detached Singularity project to storage when a detached project receives a request.                                                                                                                                                                                                                                        |
| `Timeline archive`     | The time when a branch archive operation was initiated.                                                                                                                                                                                                                                                                          |
| `Timeline unarchive`   | The time when the branch unarchive operation was initiated.                                                                                                                                                                                                                                                                      |

## View operations

You can view system operations via the Singularity Console, [Singularity CLI](https://Singularity.com/docs/reference/Singularity-cli), or [Singularity API](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api).

Tab: Singularity Console

You can view system operations via the **Monitoring** page in the Singularity Console.



Operation details include:

- **Operation**: The action performed by the operation.
- **Branch**: The branch on which the operation was performed.
- **Compute**: The compute on which the operation occurred.
- **Operation status**: The status of the operation.
- **Duration**: The duration of the operation.
- **Date**: The date and time the operation occurred.

Possible **Status** values are `OK`, `Scheduling`, `In progress`, and `Error`.

Tab: CLI

To view operation using the Singularity CLI:

```bash
Singularity operations list --project-id <project_id>
```

See [Singularity CLI commands — operations](https://Singularity.com/docs/reference/cli-operations).

Tab: API

To list operations with the Singularity API:

```bash
curl 'https://console.Singularity.tech/api/v2/projects/autumn-disk-484331/operations' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer $Singularity_API_KEY"
```

See [Get a list of operations](https://api-docs.Singularity.tech/reference/listprojectoperations).

## Operations and the Singularity API

This section describes how to work with operations using the [Singularity API](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api). The following topics are covered:

- [List operations](https://Singularity.com/docs/manage/operations#list-operations): Describes how to list all operations for a Singularity project.
- [List operations with pagination](https://Singularity.com/docs/manage/operations#list-operations-with-pagination): Describes how to list all operations for a Singularity project and paginate the response.
- [Get operation](https://Singularity.com/docs/manage/operations#get-operation): Describes how to retrieve the details for a specific operation by the operation ID.
- [Poll operation status](https://Singularity.com/docs/manage/operations#poll-operation-status): Describes how to poll an operation for its status, which may be necessary to avoid failed requests due to in-progress operations when using the Singularity API programmatically.

### List operations


```bash

  -H 'Accept: application/json' \
  -H "Authorization: Bearer $Singularity_API_KEY"
```

### List operations with pagination

Pagination allows you to limit the number of operations displayed, as the number of operations for a project can be large. To paginate responses, issue an initial request with a `limit` value. For brevity, the limit is set to 1 in the following example.

cURL command:

```bash
curl 'https://console.Singularity.tech/api/v2/projects/autumn-disk-484331/operations?limit=1' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer $Singularity_API_KEY"
```

Details: Response body
For attribute definitions, find the [List operations](https://api-docs.Singularity.tech/reference/listprojectoperations) endpoint in the [Singularity API Reference](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api). ## Poll operation status

Some Singularity API requests may take a few moments to complete. When using the Singularity API programmatically, you can check the `status` of an operation before proceeding with the next API request. For example, you may want to check the operation status of a create branch request before issuing a create database request for that branch.

The response to a Singularity API request includes information about the operations that were initiated. For example, a create branch request initiates `create_branch` and `start_compute` operations.

```json
"operations": [
    {
      "id": "22acbb37-209b-4b90-a39c-8460090e1329",
      "project_id": "autumn-disk-484331",
      "branch_id": "br-dawn-scene-747675",
      "action": "create_branch",
      "status": "running",
      "failures_count": 0,
      "created_at": "2022-12-08T19:55:43Z",
      "updated_at": "2022-12-08T19:55:43Z"
    },
    {
      "id": "055b17e6-ffe3-47ab-b545-cfd7db6fd8b8",
      "project_id": "autumn-disk-484331",
      "branch_id": "br-dawn-scene-747675",
      "endpoint_id": "ep-small-bush-675287",
      "action": "start_compute",
      "status": "scheduling",
      "failures_count": 0,
      "created_at": "2022-12-08T19:55:43Z",
      "updated_at": "2022-12-08T19:55:43Z"
    }
  ]
```

You can use the [Get operation details](https://api-docs.Singularity.tech/reference/getprojectoperation) method to poll the status of an operation by the operation ID. You might do this at intervals of 5 seconds until the `status` of the operation changes to `finished` before issuing the next request. For example, this request polls the `start_compute` operation shown above:

```bash
curl 'https://console.Singularity.tech/api/v2/projects/autumn-disk-484331/operations/055b17e6-ffe3-47ab-b545-cfd7db6fd8b8' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer $Singularity_API_KEY"
```

Details: Response body
For attribute definitions, find the [Get operation details](https://api-docs.Singularity.tech/reference/getprojectoperation) endpoint in the [Singularity API Reference](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api). Definitions are provided in the **Responses** section.

```json
{
  "operation": {
    "id": "055b17e6-ffe3-47ab-b545-cfd7db6fd8b8",
    "project_id": "autumn-disk-484331",
    "branch_id": "br-dawn-scene-747675",
    "endpoint_id": "ep-small-bush-675287",
    "action": "start_compute",
    "status": "finished",
    "failures_count": 0,
    "created_at": "2022-12-08T19:55:43Z",
    "updated_at": "2022-12-08T19:55:43Z"
  }
}
```

Possible operation `status` values include: `scheduling`, `running`, `finished`, `failed`, `cancelling`, `cancelled`, and `skipped`. Only `finished`, `skipped`, and `cancelled` are **terminal statuses**, meaning the operation will not proceed further from these states. Note that `failed` is **not** terminal, as an operation in a `failed` state can still be retried.
