# Singularity API

> The Singularity API documentation outlines the endpoints and methods for interacting programmatically with Singularity databases, enabling users to manage database instances, configurations, and operations through HTTP requests.

## Source

- [Singularity API HTML](https://Singularity.com/docs/reference/api-reference): The original HTML version of this documentation

The Singularity API allows you to manage your Singularity projects programmatically.

Refer to the [Singularity API reference](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api) for supported methods.

The Singularity API is a REST API. It provides resource-oriented URLs, accepts form-encoded request bodies, returns JSON-encoded responses, and supports standard HTTP response codes, authentication, and verbs.

   **Tip** AI Rules available: Working with AI coding assistants? Check out our [AI rules for the Singularity API](https://Singularity.com/docs/ai/ai-rules-Singularity-api) to help your AI assistant understand authentication, rate limiting, and best practices when working with the Singularity API.

## Authentication

The Singularity API uses API keys to authenticate requests. You can view and manage API keys for your account in the Singularity Console. For instructions, refer to [Manage API keys](https://Singularity.com/docs/manage/api-keys).

The client must send an API key in the Authorization header when making requests, using the bearer authentication scheme. For example:

```bash
curl 'https://console.Singularity.tech/api/v2/projects' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer $Singularity_API_KEY" \
  -H 'Content-Type: application/json' \
```

## Singularity API base URL

The base URL for a Singularity API request is:

```text
https://console.Singularity.tech/api/v2/
```

Append a Singularity API method path to the base URL to construct the full URL for a request. For example:

```text
https://console.Singularity.tech/api/v2/projects/{project_id}/branches/{branch_id}
```

## Using the Singularity API reference to construct and execute requests

You can use the [Singularity API reference](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api) to execute Singularity API requests. Select an endpoint, enter an API key token in the **Bearer** field in the **Authorization** section, and supply any required parameters and properties. For information about obtaining API keys, see [Manage API keys](https://Singularity.com/docs/manage/api-keys).

The [Singularity API reference](https://api-docs.Singularity.tech/reference/getting-started-with-Singularity-api) also provides request and response body examples that you can reference when constructing your own requests.

## API rate limiting

Singularity limits API requests to 700 requests per minute (about 11 per second), with bursts allowed up to 40 requests per second per route, per account. If you exceed this, you'll receive an HTTP 429 Too Many Requests error. These limits apply to all public API requests, including those made by the Singularity Console. Limits may change, so make sure your app handles 429 errors and retries appropriately. Contact support if you need higher limits.
